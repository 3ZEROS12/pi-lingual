# pi-lingual

Pi Coding Agent のためのバイリンガル・ターミナル HUD ＆ プロンプト最適化エンジン。

母国語で思考し、コードを書く。入力欄の上にシリコンバレーの自然な口語表現と公式ドキュメント英語をリアルタイム表示。さらにプロンプトを自動で標準的な技術英語へと書き換え、コード・コメント・コミットログの英語品質を一貫して保ちます。

## クイックスタート

Pi ターミナルから直接インストールできます：

```bash
pi install npm:pi-lingual
```

インストール後すぐに使用可能。セッション起動時に OS の言語環境（`ja ⇄ en` や `zh ⇄ en`）を自動検出し、初回起動時の対話プロンプトなしで起動します。現在のセッション認証情報をそのまま活用するため、追加の API キー設定は不要です。

> 💡 **推奨ターミナルモード**:  
> 伴走学習と過去ログの確認には、`~/.pi/agent/settings.json` で `"tuiMode": "regular"` を設定することをおすすめします。翻訳カードと語彙学習履歴が会話ストリームとともに自然にスクロールし、いつでも過去の表現を振り返ることができます。
>
> ⚡ **レイテンシ特性**: デフォルトの伴走モード（Companion）では、プロンプトは遅延 0ms でコーディングエージェントに直接パススルーされます。書き換えモード（`direct` や `live-flow`）では、モデルの応答速度に応じた単一のリクエストでプロンプトを変換します。

## 開発者が直面する 4 つの課題を解決

ターミナル AI コーディングエージェントを日常的に使う中で生じる、以下の摩擦を解消します：

### 1. チームや OSS リポジトリで求められる英語の統一
グローバルなオープンソースや英語ベースのチームでは、コード内コメント、コミットメッセージ、PR の説明文はすべて英語で記述する必要があります。
母国語で AI に指示を出すと、生成されるコードのコメントや解説まで母国語になってしまい、プッシュ前に手動で修正する手間が発生します。
仕様変換モード（`direct` / `lazy`）を使えば、日本語で普段通りに思考・入力するだけで、`pi-lingual` が指示を正確な技術英語へと自動整形してからエージェントに渡します。**生成されるコード、コメント、ドキュメントは最初から美しい英語に統一されます。**

### 2. コード生成中の 5 秒間を活用する伴走学習
Enter キーを押した後、LLM がコードを生成するまでには通常 5〜15 秒ほどの待機時間があります。
ブラウザを開くには短すぎ、何もしないには手持ち無沙汰な時間です。
`pi-lingual` は入力欄のすぐ上に、認知負荷の低い視覚的カードを表示します。生成を待つわずかな合間に、同じ思考が日米の開発現場（Slack やスタンドアップ）でどう口語表現され、設計書や PR でどうフォーマルに書かれるのかを自然とインプットできます。

### 3. 会話コンテキストを汚さない（余計なトークン消費ゼロ）
一般的な翻訳拡張機能は、プロンプトの末尾に英訳を結合してエージェントに送ります。
会話ターンが重なるにつれて重複したテキストが履歴に蓄積し、コンテキスト枠を圧迫してモデルの推論精度を鈍らせてしまいます。
`pi-lingual` はエージェントの会話履歴の外側で動作する独立した TUI オーバーレイです。**プロンプト履歴は 100% クリーンな状態を保ち、無駄なトークンを一切消費しません。**

### 4. 枠崩れのない堅牢なターミナルレイアウト
全角文字（日本語や漢字）はターミナル上で 2 カラム分の表示幅を占有します。
従来の四角いボックス枠（`│ ... │`）は文字幅の計算ズレで枠線がちぎれ、行ズレやカーソルの乱れを引き起こします。
`pi-lingual` は閉じた外枠を廃止し、Unicode UAX #11 に準拠したオープンな左レールツリー構造（`· ┌ ├ └`）を採用。幅の狭い分割ペインでもレイアウトが破綻しません。

## 3 つのコア動作モード

| モード番号・識別子 | 実行動作 | HUD 表示 | ユースケース |
| :--- | :--- | :--- | :--- |
| **[1] 伴走モード (`companion`)** | 0ms 原文パススルー | 開放型ツリー伴走カード | 日本語で素早く思考しながら、裏で自然な口語・文書表現をストックする（デフォルト） |
| **[2] 仕様変換 (`direct`)** | プロンプト自動英語化 | 1 行コンパクト表示 | 日本語の雑なメモを、エージェントが最も誤解なく動く厳密な技術英語指示に変換 |
| **[3] ライブ校正 (`live-flow`)** | 英語プロンプトの誤脱修正 | 修正前後の差分カード | 自分で書いた英語プロンプトの前置詞・語順・構文ミスを自動修復 |
| **[0] オフ (`off`)** | 完全スルー | 非表示 | 0 ピクセル、0 リスナー、0 トークン消費 |

## 2 層の操作モデル：日常のシンプルさ ＋ AI による自動設定

「日常の操作は 5 秒で覚えられ、細かなカスタマイズは AI エージェントに任せる」という設計思想を徹底しています。

### 1. 第 1 層：日常の操作（覚えるコマンドは実質 1 つ）
* **モード切替**: `/lingual`（または短縮エイリアス `/l`）と入力すると、インタラクティブなカプセル選択画面が表示されます。数字キー `1` / `2` / `3` / `0` を押すだけで、Enter キーなしで即座に切り替わります（`/lingual 1` など直接指定も可能）。
* **言語切替**: `/lang ja` や `/lingual lang ja` で、翻訳先の言語を即座に変更できます。
* **スマートバイパス**: 母国語を入力すれば伴走カードが展開され、純粋な英語（英数字・記号のみ）を入力した場合は 0ms でエージェントへ直接パススルーされます。

### 2. 第 2 層：AI スキルを通じた自然言語カスタマイズ
カスタム設定を行いたい場合も、**設定ファイルを直接編集する必要はありません。Pi エージェントに普段の言葉で指示するだけです**。内蔵の `lingual-tuner` スキルが意図を理解し、設定を安全に更新します：
* *「コミットメッセージ専用のモードを追加して」* ➔ Conventional Commits に準拠した設定を自動構成
* *「伴走カードの高さを抑えて、1 行のコンパクト表示にして」* ➔ `compact` レイアウトへ自動変更
* *「解説言語を日本語から英語に変えて」* ➔ 言語ペアと認知補助言語を自動調整

## 整理されたコマンド構成（単一スーパーコマンド `/lingual` ＆ `/l`）

Pi の `/` コマンドメニューを汚さないよう、登録されるトップレベルコマンドは `/lingual`（および超短縮エイリアス `/l`）と `/lang` のみに絞り込まれています：

| コマンド | 引数・サブコマンド | 説明 |
| :--- | :--- | :--- |
| **`/lingual`** / **`/l`** | *(引数なし)* | カプセル選択 UI を開く（`1`/`2`/`3`/`0`、矢印キー、`Esc` でキャンセル） |
| ↳ 直接切替 | `/lingual 1` \| `2` \| `3` \| `0` | モード番号または ID（`companion`, `direct`, `live-flow`, `off`）で直接切替 |
| ↳ オン／オフ | `/lingual on` \| `off` | 伴走モードの即時有効化または完全オフ（0 ピクセル、0 トークン） |
| ↳ 言語ペア | `/lingual lang [pair]` または `/lang` | 翻訳方向の切替（例：`/lang ja`, `/lingual lang ja en`） |
| ↳ 再表示 | `/lingual last` \| `replay` | 直前に生成された伴走カードや差分カードを再表示 |
| ↳ レイアウト | `/lingual compact` | 1 行カプセル表示と開放型ツリー HUD のトグル切替 |
| ↳ モードロック | `/lingual lock` \| `unlock` | 現在の動作モードを固定し、外部スクリプト等による予期せぬ変動を防止 |
| ↳ 推論深度 | `/lingual reasoning [low\|medium\|high]` | モードごとの推論思考レベルを設定（日常は `low`、仕様策定は `medium`） |
| ↳ 設定チューナー | `/lingual tuner [要求]` | 自然言語によるプロンプト設計ウィザードを起動 |
| ↳ 状態診断 | `/lingual status` | キャッシュヒット率や現在の動作状態を表示 |

*キーボードショートカット：`Alt+.`（次の候補）、`Alt+,`（前の候補）。スタンドアロン CLI：`lingual "prompt"`。*

## 動的スロットアーキテクチャ（表示項目の自由な組み換え）

伴走カードに表示される各スロットは完全にモジュール化されており、自由に増減・並び替えが可能です：

- **原文の行を非表示にする**:  
  `/lingual slots rm source` を実行すると、原文行が非表示になり、翻訳結果のみがスマートに表示されます。
- **好みのトーンやカスタムスロットを追加する**:  
  `/lingual slots add twitter Tweet 280文字以内の洗練されたツイート` のように追加すると、プロンプトのスキーマと HUD レイアウトがリアルタイムに追従します。
- **一時的なミュートと初期化**:  
  `/lingual slots toggle <id>` で一時的にスロットを非表示にし、`/lingual slots reset` でいつでも初期状態に戻せます。

## 専用モデルとプライバシー配慮

### 推論深度の動的調整 (`/lingual reasoning`)
`pi-lingual` では、用途に応じてモデルを切り替える代わりに、モードごとの推論深度（Reasoning Effort）を調整できます：
```bash
/lingual reasoning low       # 応答速度を最優先（日常の仕様書き換えや校正向け）
/lingual reasoning medium    # 思考の深さを重視（複雑な仕様書へのブレインダンプ展開向け）
/lingual reasoning high      # 厳密な多重制約プロンプト向け
```

### 上位モデルのトークン枠を保護する
高推論モデルで作業している際、伴走翻訳の処理を軽量モデルにオフロードして枠を節約できます：
```bash
/lingual model <軽量モデルID>    # 伴走処理のみ特定モデルに委譲
/lingual model auto              # メインセッションのモデルに追従
```

ローカルの Ollama や OpenAI 互換エンドポイントも `~/.pi/agent/lingual.json` から設定可能です：
```json
{
  "endpoint": "http://127.0.0.1:11434/v1/chat/completions",
  "model": "qwen2.5:3b"
}
```

> 🔒 **プライバシーの保証**: `pi-lingual` は外部依存ゼロ（`dependencies: {}`）で設計されており、テレメトリや外部収集サーバーは一切存在しません。リクエストはお手元の認証済みモデルエンドポイントのみに送信されます。

## 開発者のノート

翻訳モデルのシステムプロンプトは現在デフォルトで調整済みですが、`/lingual tuner` コマンドや内蔵の `lingual-tuner` スキルを使って、いつでもご自身の好みに合わせてカスタマイズできます。

単なる設定の変更にとどまらず、ご自身が本当に欲しい出力スタイルをぜひ考えてみてください：
* **重要語句の分解はどの程度の細かさが心地よいか？**
* **文法やエンジニアリング背景の補足説明は必要か？**
* **一度に目にする重要表現は、何個くらいが認知負荷として適切か？**

これらを自分に合わせてチューニングすることで、はじめて最高の効果が得られます。日常のコーディングで Enter を押し、AI がコードを生成するまでの数秒間、入力欄の上にふと目を向けてみてください。

このプロジェクトを着想した背景には、従来の辞書引きや単語帳アプリに対する個人的な挫折がありました。基礎的な単語はすでに知っており、難解な語彙は文脈のない辞書をいくら眺めても身につかないというジレンマです。実際に言葉を身につけ、使えるようになるために必要なのは、現実の開発現場の文脈に即した自然なフレーズと生きたコロケーションです。

自分にとって最も心地よいプロンプトを整え、コード生成の合間の時間を味方につけて、無理なく続けていただければ幸いです。
